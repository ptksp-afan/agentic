## Defect

Tidak ada defect (D-n) pada ED-1027. Catatan (tidak mengubah verdict):

- **O-1 (pesan ARCHIVE417).** `GET verifications/{id dokumen}` mengembalikan 400 dengan teks "Opname can only be run on a folder" / "Opname hanya bisa dijalankan pada folder" (diukur di kedua bahasa). Sesuai spec BR-16 dan kontrak §3 (pakai ulang kode 03); hanya teksnya menyebut opname. Sudah ditandai dev di run.md untuk konfirmasi; tidak perlu tindakan QA.
- **O-2 (HTTP 500 lama pada list).** `GET archives` dengan `sorts` bentuk array bersarang (`sorts[0][sortBy]=name&sorts[0][sortType]=desc`; FE mengirim `sorts[0]=<JSON>`), `pagination=abc`, `search[]=x` dan sejenisnya = 500. Saya mengalaminya di draf pertama skenario sort saya (bentuk sort salah), lalu memperbaiki skenario. Penyebabnya di baris yang tidak disentuh diff ED-1027 (`CustomizeBuilder::scopeSortAll`, `$request->pagination`); sudah dikarakterisasi ED-1025 `X-12`/`X-13` (keluarga ED-1070) dan `X-13` ED-1025 PASS pada regresi ini, artinya himpunan kasus 500 tidak berubah oleh ED-1027. Endpoint baru `verifications` tidak menerima parameter dan tidak pernah 5xx (X-6, AC-8). Developer yang memutuskan penanganan ED-1070.
- **O-3 (updater_logs).** Tabel `updater_logs` di `api_sidomaju` tidak memuat Updater ED-1025/1026/1027 (log terakhir 2026-09-21): dev menjalankannya langsung. Efeknya terbukti benar di DB (AC-1) dan jalur runner nyata `UpdateVersionController::executeUpdater` diuji di `X-1` (log sukses, baris log uji dihapus kembali). Pada deploy Updater berjalan lewat alur update biasa.

Konfirmasi dev (dari run.md) yang diperiksa dan konsisten dengan spec: `folder_verified` = jumlah `archive_opname_folders.verified_count` (hasil scan Verified, BR-11 "hasilnya Verified di sesi itu"); "mencakup F" memakai pohon folder sekarang (AC-11, terbukti lewat pemindahan folder); sesi di overview bisa belum bisa dibuka lewat `GET opnames/{id}` (hanya pemilik/superadmin sampai 05; K-5 a).

## Isolasi tenant & permission

- **Permission (semua endpoint baru):** `GET verifications` dan `GET verifications/{id}` dijaga `permission_v5:List Archive` (diff route). Diizinkan: role 3 (QA_USER), role 29 (List Archive saja), role 1/2, QA_USER2 (Sales Supervisor) = 200. Catatan alat: untuk QA_USER2 (bukan tipe karyawan) role 6 membuat middleware `PermissionVersion5::allowAccessWebsite` mencabut token (perilaku lama), jadi X-9 memakai role 22.
- **Isolasi tenant: tidak bisa diverifikasi lewat HTTP.** `QA_DBS` hanya `api_sidomaju`, jadi `X-3` (`$t->isolation`) berstatus SKIP. Pengganti, tinjauan kode: `VerificationService` dan `VerificationController` tanpa `static`, `Cache::`, `global`, atau properti pembawa data lintas request (satu-satunya kemunculan kata static adalah komentar); konteks dihitung per request dan diteruskan lewat parameter; controller membuat `new VerificationService` per request; diff `ArchiveService` hanya menambah pemanggilan lokal. Risiko kebocoran di fpm/RR rendah; satu uji dua-DB tetap dianjurkan bila DB kedua disiapkan.
- **Tinjauan kebenaran diff BE** (7 berkas): 3 route sesuai tabel endpoint spec §4 (prefix `verifications` sendiri, tanpa bentrok `archives/{id}`); kontrak vs respons nyata cocok untuk `result.columns`, `data[].document_verified` (`{verified,total}`/`null`), `document_verified_summary`, bentuk `GET verifications` dan `{id}`, `session_row` (+ `folder_total_documents`/`folder_verified`), body 403/404/400, `msg_code` `ARCHIVE200`; urutan cek id sesuai kontrak (tak ada 404 -> lokasi 403 -> dokumen 400 -> nonaktif 404 -> View 403); tanpa tabel/kolom baru (Updater hanya mereset display setting, terdaftar kunci terbesar), tanpa permission atau kode pesan baru, tanpa tulisan data (baca saja, tanpa transaksi, tidak ada rollback yang perlu diuji); kolom v3 tidak berlaku (Archive tidak ada di v3); folder berputar tidak membuat loop (`X-4`).
